⏺ Code Understanding Summary

  Bookchop is a client-side PDF annotation tool with AI-assisted annotation capabilities. Here's what I understand:

  Architecture

  - Client-side only: No backend required, runs entirely in browser
  - Two main interfaces: Annotator for creating annotations, Viewer for displaying cropped regions
  - Technology stack: TypeScript, Tailwind CSS, PDF.js, Playwright for testing

  Core Components

  1. Annotator (annotator.ts)
  - Interactive PDF annotation creation via click-drag
  - Resizable/movable annotations with 8 resize handles
  - Fractional coordinate system (0.0-1.0) for resolution independence
  - AI-assisted annotation using Gemini API
  - Save/load annotations as JSON files
  - Sidebar management with hover effects and navigation

  2. Viewer (viewer.ts)
  - Displays cropped regions from annotations
  - Takes PDF + JSON annotations, extracts just the annotated areas
  - Navigation between annotation regions
  - Useful for reviewing/presenting annotated content

  3. AI Integration (ai-engine.ts, ai-orchestrator.ts)
  - Engine: Headless Gemini API interface with structured JSON responses
  - Orchestrator: Browser bridge handling prompts, API keys, few-shot examples
  - Few-shot learning from previously annotated pages
  - User-configurable prompts for different annotation styles

  4. Shared Utilities (pdf-utils.ts)
  - PDF.js initialization and worker setup
  - Annotation data structures and JSON parsing
  - ID generation utilities

  Data Format

  Annotations stored as JSON with:
  - Metadata (source PDF, version, timestamp)
  - Page-grouped annotations with fractional coordinates
  - Simple string labels (unopinionated format)

  Key Design Principles

  - Deep modules philosophy: Only abstract truly complex functionality
  - Static hosting friendly: No server dependencies
  - Resolution independent: Fractional coordinates work across displays
  - Event-driven: Mouse interactions, file uploads, annotation management

  The codebase is well-structured, follows good separation of concerns, and implements defensive AI integration with proper error handling and user prompts.

  4. Cross-Site Scripting (XSS) Vulnerability

  - Problem: If the site has XSS vulnerabilities, malicious scripts can access localStorage

  2. Going to Application/Storage tab
  3. Expanding "Local Storage"
  4. Finding the gemini-api-key entry

  Potential Abuse:

  - API Quota Theft: Malicious actors could use stolen keys for their own API calls
  - Cost Issues: Unexpected charges on the user's Gemini API account
  - Data Exposure: Access to user's API account and usage patterns

  Better Alternatives:

  For Production:

  1. Server-side proxy: API calls go through your server, keys stored securely server-side
  2. OAuth/Token-based auth: Use short-lived tokens instead of permanent API keys

  function createAnnotationsFromWordGroups(response: any[], words: Word[], pageWidth: number, pageHeight: number) {
    return response.map(region => {
      // Validate that the word indices exist
      const regionWords = region.wordIndices.map(i => words[i]).filter(Boolean);

      if (regionWords.length === 0) {
        console.warn('No valid words for region:', region);
        return null;
      }

      // Calculate precise bounding box from actual words
      const xmin = Math.min(...regionWords.map(w => w.xmin));
      const xmax = Math.max(...regionWords.map(w => w.xmax));
      const ymin = Math.min(...regionWords.map(w => w.ymin));
      const ymax = Math.max(...regionWords.map(w => w.ymax));

      // Convert to fractional coordinates
      return {
        id: generateId(),
        x: xmin / pageWidth,
        y: ymin / pageHeight,
        width: (xmax - xmin) / pageWidth,
        height: (ymax - ymin) / pageHeight,
        label: region.label,
        semanticType: region.semanticType,
        pageNumber: pageNumber,
        wordIndices: region.wordIndices, // Store for future reference
        ocrText: regionWords.map(w => w.text).join(' ')
      };
