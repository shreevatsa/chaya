> Let's think about this interface a bit further. What exactly will it return? Why does it already take an `allAnnotations`?

✦ Excellent questions. Thinking through the details of the interface is crucial for creating a good abstraction. Let me clarify.

  1. What exactly will it return?


  It returns a Promise that resolves to one of two things:


   1. An array of `Annotation` objects (`Annotation[]`): This is the "success" case. If the user completes the AI prompt and the process finishes, the function returns an array containing only the newly generated 
      annotations. The calling code (annotator.ts) is then responsible for taking this new array and adding its contents to the main annotations list and updating the UI.


   2. `null`: This is the "user cancelled" case. If the user closes the AI prompt dialog without running the tool (by clicking "Cancel" or clicking outside the dialog), the Promise resolves to null. This is a clear signal
      to the caller that no action should be taken. It's not an error, just a neutral outcome.


  If an actual error occurs during the process (e.g., the Gemini API call fails), the Promise will be rejected, which can be caught with a .catch() block.

  2. Why does it take allAnnotations as an argument?

  This is the most important reason for this particular interface design. The AI annotation feature is more sophisticated than just sending an image and getting back rectangles.


  It uses a technique called few-shot prompting to improve the quality of the results. Here's how it works:


   1. The AI module looks at the allAnnotations array you provide.
   2. It finds annotations the user has already created on other pages.
   3. It takes up to two of these previously annotated pages (both the image and the JSON data for the boxes) and includes them in the prompt to the Gemini API as examples of good annotations.


  By showing the AI examples of the user's preferred annotation style (e.g., how they label headings vs. paragraphs, the level of detail they use), it can generate new annotations for the current page that are far more
  consistent and accurate.


  In short, the AIAnotator needs allAnnotations not to modify them, but to learn from them to provide better suggestions. It's a read-only dependency that dramatically improves the feature's quality.
